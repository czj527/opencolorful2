# t7 验收门禁与本地真实发布规范（防假绿）

> 输入：t2 §4 MVP 验收口径（全新机器一次跑通 / 端到端点击链路 / P0 治理可演示 / 文档节制）、
> t2 §2 MVP 边界、t3 §3 CI 门禁与 §4 发布流程、t1 §4 P0 治理 1–5。
> 定位：本文件是**发布判定规则**（verdict 机），不是实现方案；只写这一个文件，证据落 `dist/`，不新增仓内文档目录。

## 0. 一句话规则与适用范围

- 一句话：**没有真实产物、没有原始日志、没有可复现链路 ID 的"通过"一律不成立。**
- 适用于 M1 每次发布判定（本地自用发布同样执行，不做"自己人不走门禁"的例外）。
- 不做：不重复 t3 CI 的 lint/type/test/build/ratchet（见 §5），不评估二期项（网关/多 Agent/cron/向量检索）。

## 1. 本地真实发布 = 什么算产物

### 1.1 真实发布产物定义

一次"本地真实发布"= 以下 5 项同时存在且互相自洽，缺一即**不是发布**：

| # | 产物 | 路径/形态 | 判定要求 |
|---|---|---|---|
| P1 | 桌面端构建产物 | `dist/release/<version>/agentplant-desktop-<version>-win-x64.exe`（或 `win-unpacked/` 解包目录 + 启动 exe） | 由 `pnpm build` 真实生成；**不得**指向源码目录或 dev server |
| P2 | 版本戳四方一致 | 产物文件名 / 根 `package.json` version / `git tag v<version>` / 应用内显示（`app.getVersion()` 或关于页） | 四处全等；版本号格式 `YYYY.M.PATCH`（t3 §4） |
| P3 | 产物清单 | `dist/release/<version>/release-manifest.json` | 含 `version`、`gitSha`、`buildTime`、OS/arch、Node/pnpm 版本、每个产物的 `sha256`+`size`、生成命令原文 |
| P4 | 校验文件 | `dist/release/<version>/SHA256SUMS.txt` | 现场重算 `sha256` 与文件内容逐行一致 |
| P5 | 冒烟原始日志 | `dist/release/<version>/evidence/` 下每链路一份 `AT-xxx.log` | 原始 stdout/stderr + exit code + 时间戳 + 机器标识；**不收**转述、截图代替日志、实现者手写"已通过" |

判定前置断言：`release-manifest.json.gitSha` 必须等于被验收的 `git rev-parse HEAD`。
若产物生成早于最后一次源码提交（`buildTime` < 提交时间）→ 直接 blocked（陈旧产物）。

校验方式（一条命令，待落地，owner: t3）：
`node scripts/verify-release.mjs dist/release/<version>` → 校验 P1–P4 存在性、sha256、版本戳四方一致，
输出 `VERIFY-OK <version> <gitSha>` 或非 0 退出。该脚本不产生新仓目录。

### 1.2 假绿判例（FG：必须识别并当场判 blocked）

| ID | 判例 | 识别方法（可机械执行） |
|---|---|---|
| FG-01 | **dev-only 冒充发布**：用 `pnpm dev` 起的 Vite dev server / 未打包 `electron .` 演示"桌面端可跑" | 产物目录不存在或为空；进程命令行含源码路径/dev 端口；`buildTime` 晚于验收却无 `gitSha`；UI 中版本显示为 `0.0.0`/`dev` |
| FG-02 | **源码直跑冒充一键可跑**：`tsx packages/agent-core/src/cli.ts` 走通聊天即宣称"一键可跑" | 运行时为 `.ts` 直执行；无 exe/解包产物；文档中"一键"命令未出现在根 `package.json` scripts |
| FG-03 | **桩/回放冒充工具调用**：硬编码文件内容、mock LLM 回放、假 search 结果 | 断网后网页搜索仍"成功"；写文件后目标文件不存在或内容/mtime 不符；执行命令无真实 exit code；日志无请求/工具调用 ID |
| FG-04 | **同进程 reload 冒充重启不丢**：关窗不退出、内存缓存重读、或先 seed 数据再"验证召回" | 重启前后进程 PID 未变；`.sqlite`/`-wal` mtime 未变；把候选记忆删除后再重启仍能召回（说明读的是缓存或种子） |
| FG-05 | **版本戳/校验自证**：UI 硬编码版本号、`SHA256SUMS.txt` 未随产物更新 | 四方版本比对不齐；现场重算 sha256 与清单不符；tag 指向的 sha ≠ `gitSha` |
| FG-06 | **门禁自证**：以"我已经测过了"文本、skip 的用例、本地 IDE 绿勾作为证据 | 要求原始 `AT-xxx.log`；grep 证据目录中 `-t skip` / `.skip(` / `it.todo`；证据文件时间戳落在验收窗口之外 |
| FG-07 | **环境残留冒充全新机器**：在已装好 `node_modules`/已存在用户数据目录的机器上跑"全新机器一次跑通" | 按 §4 F-02 清场断言逐条检查；`%APPDATA%` 下已存在应用数据；install 日志中出现"Already up to date" |

任一 FG 成立：**整条发布 blocked**，不允许"改天补证据"后沿用本次 verdict。

## 2. 防假绿门禁矩阵

判定符号：**pass** = 该行全部产物要求 + 链路证据齐备且无阻塞缺陷；**blocked** = 触达任一 blocked 条件，整条发布打回、不得带缺陷发布。
"阻塞性缺陷"= 该功能在主链上不可用或治理语义被破坏（对照 §3 定级表）。

| MVP 功能 | 发布产物要求 | 链路ID | 阻塞性缺陷（blocker） | pass 条件 | blocked 打回条件 |
|---|---|---|---|---|---|
| 聊天主循环 | P1（可启动的打包产物）+ P2 | AT-201、AT-202 | 输入无响应；回复不流式或截断无报错；助手回合未落库；刷新/重启后会话丢失 | 两条链路日志完整、exit 0、会话可查 | 任一条断链；或仅 dev 产物下可走通（FG-01） |
| 工具调用 | P1 + P3（工具清单形态需在 manifest 可查） | AT-301、AT-302、AT-303、AT-304 | 四个工具中任一个无法通过真实产物触发；命令无真实 exit code；写文件未落盘；无工具调用审计 | 四链路全 pass（AT-304 允许受网络影响，见 §3 严重级） | 工具调用被 mock 回放（FG-03）；或工具越权改写范围外路径 |
| 简单记忆 | P1 + P4 | AT-401、AT-402、AT-403 | 记忆不落盘；新会话无法召回；重启后丢失（偏好/事实任一） | 写入→新会话召回→重启仍在，三段证据齐备 | 召回来自缓存/种子（FG-04）；或"新会话"实为同一 session id |
| SQLite 状态内核 | P1 + P4（`*.sqlite` 为运行态，不入仓） | AT-501、AT-502 | 存在第二个运行时状态存储；未开 WAL；任务/会话/记忆非同库；CAS 领取可双成功 | 单文件 + WAL 证据 + 同库断言 + 并发双 claim 恰一成功 | 引入 Redis/MQ/JSON 落盘旁路；或 schema 变更无迁移路径声明（t3 §2） |
| P0 治理 | P1 + P5（治理证据随产物归档） | AT-502、AT-503、AT-504、AT-505、AT-506 | 见 §2.1 逐条；任一条不成立即为阻塞（治理类不允许降级为"严重"） | 5 条逐条演示通过（AT-506 可降级为单元级证据） | 任一条失败；或用"补充说明"代替行为变更 |
| 一键可跑 | P1 + P2 + P3 + P4 | AT-101、AT-102、AT-103 + §4 全清单 | 新机器需口头知识/额外手工步骤；一键命令非 0 退出；产物校验失败 | F-01…F-15 全过 + `VERIFY-OK` | 需要问实现者任何问题才能跑通 = 文档缺陷，打回 owner（同样计入 blocked） |

### 2.1 P0 治理逐条判定（治理 1–5 → 链路 ID）

| 治理项（t1 §4） | 链路ID | 通过判据（行为级） |
|---|---|---|
| 1 终态不可降级 | AT-503 | `completed`/`failed` 落定后任何回退写入被拒绝并显式报错（非静默忽略） |
| 2 CAS 领取 | AT-502 | 并发两次 claim 同一任务：恰一个成功，另一个返回冲突；无重复执行 |
| 3 进度文本≠交付 | AT-504 | 仅"我接下来要…"文本不得标记完成；正确落到 blocked/needs_input，且不消耗重试限额 |
| 4 子权限不超父 | AT-506 | 越权请求显式报错、不静默降级；单 Agent 下允许以单元级证据（测试 + exit code）替代点击链路 |
| 5 三层限额 | AT-505 | depth / 子任务数 / 并发 lane 超限均显式拒绝，且拒绝事件入审计 |

审计旁证（P1 第 7 条）：上述每一步须在 metadata-only 账本留下事件记录（只记事件元数据，**不得**记正文/参数）。

### 2.2 链路目录（步骤 + 证据）

| ID | 链路 | 关键步骤 | 证据要求（`AT-xxx.log`） |
|---|---|---|---|
| AT-101 | 全新机器一次跑通（总链） | §4 全部步骤 | 每步命令 + 输出 + exit code |
| AT-102 | 一键可跑 | 双击 exe / `pnpm start`（文档声明的那一种） | 窗口出现 + 首条输入成功 + 退出码 |
| AT-103 | 版本戳与校验 | 四方版本比对 + `verify-release.mjs` | 比对输出 + `VERIFY-OK` 行 |
| AT-201 | 聊天主循环 | 输入 → 流式输出完成 → 会话落库 | 完整流式输出 + 落库查询结果 |
| AT-202 | 多轮上下文 | 追问引用上一轮事实 | 两轮日志同一 session id |
| AT-301 | 读文件 | 指定文件内容被真实读取 | 读取内容 + 路径 |
| AT-302 | 写文件 | 写入指定路径并回读 | 落盘路径 + `mtime` + 内容 |
| AT-303 | 执行命令 | 执行命令并返回真实退出码 | 命令行 + stdout/stderr + exit code |
| AT-304 | 网页浏览/搜索 | 真实取回一个页面/搜索结果 | 请求 ID + 结果摘要（断网即失败） |
| AT-401 | 记忆写入 | 声明一条偏好/事实并落库 | 写入记录 + DB 查询 |
| AT-402 | 跨会话召回 | 新建会话后召回上一步记忆 | 新 session id + 召回内容 |
| AT-403 | 重启不丢 | 完全退出（PID 变）后重开 | 前后 PID 对比 + 数据仍在 |
| AT-501 | SQLite 单库 + WAL | 断言单文件、WAL 生效、三域同库 | 文件列表 + `PRAGMA journal_mode` 输出 |
| AT-502 | CAS 领取 | 并发双 claim | 两次调用结果 + 仅一次执行 |
| AT-503 | 终态不可降级 | 终态后回退写入 | 拒绝报错原文 |
| AT-504 | 进度文本≠交付 | 纯进度文本回传 | 实际状态（blocked）与审计事件 |
| AT-505 | 三层限额 | 逐层触发超限 | 三次拒绝报错 |
| AT-506 | 子权限不超父 | 越权请求 | 显式报错原文（或单元级证据） |

## 3. 阻塞缺陷打回流程

### 3.1 发现 → 定级 → 打回 → 复验

1. **发现**：任何验收人（含本人自检）在真实产物上复现到问题 → 立即按 §2.2 记录链路 ID + 原始日志，写入 `dist/release/<version>/evidence/`。
2. **定级**（唯一权威表）：

| 级别 | 定义 | 处置 |
|---|---|---|
| 阻塞 blocker | 任一 AT 主链断；产物不存在/不符（FG-01/02/05）；假绿成立；数据丢失；终态可降级；治理语义被破坏 | 整条发布 **blocked**，禁止发布；必须修复 + 同 ID 全链复验 |
| 严重 major | 链路可走通但语义错（审计写入正文、无 CAS、限额未生效）；非主链工具失败；网络致 AT-304 间歇失败；文档缺步骤需口头补充 | 不得判"通过"；修复后转 pass，或经用户显式同意降级为"遗留项 + 下一 patch" |
| 一般 minor | 文案/日志/性能/非功能性瑕疵，不影响链路与治理 | 记入验收报告"遗留项"，不阻塞，进 patch backlog |

**升格规则**：凡属 P0 治理 1–5、产物真实性、数据持久性的问题，一律按**阻塞**处理，禁止按"严重"带缺陷放行。

3. **打回路径**（按 owner 包归属，一次打回只给一个 owner）：

| 失败对象 | 打回给 | 依据 |
|---|---|---|
| `packages/agent-core/**`（聊天主循环、工具集、沙箱、提示词） | **t4** | t2 §5-4（shell 与沙箱由 t4 出方案） |
| `packages/state/**`（SQLite、会话/记忆、任务状态机与 P0 治理） | **t5** | t2 §2-4/5（状态内核与治理） |
| `apps/desktop/**`、`scripts/**`、`.github/**`、版本与产物、文档缺失 | **t3** | t3 §1/§3/§4（仓库、CI、发布流程） |

打回内容必须包含：链路 ID、级别、复现步骤、原始日志路径、期望 vs 实际、**不变更的验收口径**。
若实际 inScope 与该表不符，以 owner 任务的 `inScope` 声明为准，并同步 t7（不得据口头说法改归属）。

4. **复验要求**（缺一不算复验）：
   - 换环境：不复用缺陷发现时的缓存/进程/DB 目录（必要时换机器或清场重来）。
   - 全链重跑：重跑该链路 ID 的**完整链路**，不接受"只跑失败那一步"。
   - 原样口径：验收标准、链路 ID、步骤不得因"修不动"而放宽或改写。
   - 证据留档：新证据落 `evidence/`，旧证据保留（不得覆盖删除）。
   - 二值判定：复验只有 `pass` 或 `blocked`，不接受"基本通过/部分通过"。

### 3.2 终态不可降级语义在本流程中的体现

1. **发布记录不可回退**：某版本 verdict 一旦落 `pass`，不得改为"部分通过"或回退口径；新问题以**新版本号 + 新记录**承载。
2. **证据不可覆盖**：`evidence/` 证据只增不改；覆盖旧日志本身即按阻塞处理（等同篡改）。
3. **口径不可降级**：不允许通过调低验收标准（删链路、合并步骤、放宽 blocker 定义）让 red 变绿；口径变更只能以本文件新版本 + 用户拍板进行。
4. **缺陷状态不可降级**：blocker → minor 的"降级"不成立；要么修复，要么以用户显式授权关闭并留有记录，且关闭原因入档。
5. **与 P0 一致**：本流程对"发布"施加的规则，与产品对"任务终态"施加的规则（AT-503）同构——同一套语义，不允许对外严格、对内宽松。

## 4. 全新机器一次跑通清单（Fresh-machine checklist）

**前置条件**（缺任一项则本次验收不成立，判 blocked，不得以"环境问题"跳过）：

- 干净环境：新虚拟机 / 新用户账户 / 已按 F-02 清场的本机。
- 工具链：Node 22（t3 §3）、corepack 启用的 pnpm（版本随 lockfile）、git。
- 目标平台：Windows 10/11 x64（M1 目标），有屏幕可完成点击链路。
- 网络：可访问 LLM provider 与网页搜索；**有效 provider key**（按文档配置，`.env` 不入仓）。
  → 无 key：相关 AT 链路判 **blocked**，禁止用 mock/fake provider 换取 pass（FG-03）。
- 输入物：源码（记录 `git rev-parse HEAD`）或源码包 + 一份已生成的 `dist/release/<version>/` 产物。
- 唯一信息来源：仓内 `README` / `AGENTS.md` / `docs/decisions/*`。**若需向实现者提问才跑通 → 记为文档缺陷（t3），本次 blocked。**

| 步骤 | 动作（只用文档中的命令） | 预期输出 | 失败即阻塞 |
|---|---|---|---|
| F-01 | 记录机器信息（OS、arch、内存、Node/pnpm 版本、时间） | 一行环境摘要写入报告 | 信息缺失 |
| F-02 | 清场断言：`%APPDATA%`/`%LOCALAPPDATA%` 下无应用数据；无 `node_modules`；无 `.sqlite` 残留 | 断言全部为"不存在" | 任一存在（FG-07） |
| F-03 | 获取源码并记录 `git sha`（或校验源码包哈希） | `HEAD` = 待验收 sha | 无法确定 sha |
| F-04 | `pnpm install --frozen-lockfile` | exit 0；lockfile 无变更 | 非 0 / lockfile 被改写 |
| F-05 | `pnpm build` | exit 0；`dist/release/<version>/` 生成 | 非 0 或无产物（FG-01） |
| F-06 | `node scripts/verify-release.mjs dist/release/<version>` | `VERIFY-OK <version> <gitSha>`；sha256 全对 | 非 0（FG-05） |
| F-07 | 安装/解包产物并启动 | 桌面窗口出现，输入框可用 | 启动失败/白屏 |
| F-08 | 版本戳四方比对（UI / package.json / 文件名 / tag） | 四处全等 | 任一不等（P2） |
| F-09 | 走 AT-201 + AT-202（聊天主循环、多轮） | 流式回复完整、会话可查 | 断链 |
| F-10 | 走 AT-301…AT-304（四个工具） | 文件落盘、真实 exit code、网页结果 | 断链或 mock（FG-03） |
| F-11 | 走 AT-401 → AT-402（写入 → 新会话召回） | 新 session 召回成功 | 召回失败 |
| F-12 | 完全退出（记录 PID）→ 重开 → 走 AT-403 | PID 变化且数据仍在 | PID 未变（FG-04）/数据丢失 |
| F-13 | 走 AT-501…AT-506（内核 + P0 治理五项） | 五条判据全成立 + 审计事件存在 | 任一条失败（治理升格为阻塞） |
| F-14 | 一键命令（文档声明的唯一入口，AT-102） | exit 0 并生成 `evidence/` 日志 | 非 0 / 需手工干预 |
| F-15 | 文档节制检查：`README` + `AGENTS.md` + `design.md` + `docs/decisions/t1..t7` 齐备（澄清：t6 产出即根 `design.md` v1.0.0 本身 + `AGENTS.md` 指针，不另设 `t6-*.md`，故 F-15 对 t6 只查根 `design.md` 与指针存在） | 全部存在且与实现一致 | 缺失或与实现不符 |
| F-16 | 汇总 verdict：P1–P5 齐备 + 全链路 pass → `pass`，否则 `blocked` | 验收报告落 `dist/release/<version>/evidence/REPORT.md` | 不允许"有保留的 pass" |

## 5. 与 CI 的关系（不重复）

**t3 CI 管"每次提交在源码上的确定性门禁"（lint→type→test→build→ratchet，干净 runner，不装包、不点 UI）；t7 管"发布产物在真实机器上的端到端可点链路"（装包、点击、重启、治理行为）。**
分工边界：CI 绿是 t7 的**输入条件**（无 CI 绿的 sha 不予验收），t7 不重跑 lint/单测、不接管 CI 失败；CI 通过不代表可发布，t7 通过才发版。
