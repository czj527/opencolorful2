## 1. 体验定位

**陪伴感 × 克制 × 本地工具的信任感。**

- 陪伴感来自**在场感**（它一直在、在做什么可感知），不是通知感：无弹窗、无红点、无提示音、
  无自动切视图（依据：t1 §6 hanako 的图形/人格侧是差异化方向；t2 把"日常陪伴问答"列为第一场景）。
- 信任感来自**可见即可信**：一切越界动作（写文件/执行命令/联网）以结构化卡片留在消息流，
  参数与结果可展开、可追溯（依据：t1 §3 审计、P0-3 进度文本≠交付）。
- 载体：M1 为 Electron 桌面壳 + Web 渲染层（t3 §1 `apps/desktop`），**桌面宽屏优先**
  （min 1024px，设计基准 1440×900），移动端仅保证不破版。

## 2. 设计原则（双层，各 5 条）

**视觉层（tokens.md §1）**：P1 在场感优先于装饰感 / P2 克制用色（一个强调色 + 低饱和纸感基调）/
P3 状态可解释、后果可预期（治理信息禁情绪化）/ P4 动效只承担信息职责 / P5 桌面宽屏清晰度。

**交互层（ia-and-interaction.md §0.3）**：P1 克制不打扰 / P2 可见即可信 / P3 状态以库为准
（UI 是 `tasks.status`/`tool_calls.status` 的直接投影）/ P4 计划不是交付 / P5 失败显式
（禁止静默截断/静默降级）。

## 3. 设计系统 tokens（详见 tokens.md）

- **三层模型**：L1 原始色板（11 色相，组件禁用）→ L2 语义层（组件唯一入口，主题在此切换）→
  L3 结构层（间距/圆角/动效等恒定值）。命名 `--ap-{类}-{子类}-{变体}`，可机器解析。
- **色彩**：暖纸基调（paper/ink/night/mist 中性族）+ 单强调色 **印章青蓝 seal `#45708A`**；
  success/warning/danger/info 只承载真实语义；warning/info 刻意无实心档（MVP 无对应组件）。
- **陪伴感专属（差异化核心，占 L2 的 37%）**：
  - `presence-*` 五态：idle 中性雾蓝 / thinking 余温琥珀（呼吸 2400ms）/ streaming 品牌青 /
    acting 苔绿（节拍 900ms）/ awaiting-user 深琥珀（**静止**实心 + 2px 外环）。
    心智态=暖色、动手态=冷色的**色温通道**，用户凭色温即可分辨"在想 vs 在动手"；每态配 ≥4.5:1
    文字变体，禁止颜色当唯一信息。
  - `ambient-*` 环境氛围（≤0.12 alpha，永不承载信息）+ 时间氛围 4 段（可选增强，不进验收）。
  - `emotion-*` 情绪点缀 4 个，5 条硬约束（**禁止用于安全/治理信息**）。
- **动效**：11 档语义时长（含 breath 2400ms/pulse 900ms/caret 1000ms）+ 6 条 cubic-bezier
  （settle 过冲曲线仅限"完成/送达"一次性确认）+ 19 行状态过渡约定；reduced-motion 降级策略为
  **"换成静态可读状态"而非变快**；`--ap-motion-scale` 全局运动缩放因子。
- **主题**：默认 **auto 跟随系统**；`:root` 字面兜底浅色；暗色为体验锚点（presence/ambient
  先在暗色调优）；双主题都设 `color-scheme`；切换主题禁止对背景加过渡。
- **质量证据**：109 项对比度检查 0 项未达标（判定口径 = 每个文字 token × 9 个背景表面取最差值）；
  CSS 引用完整性脚本核验（悬空引用/死档位/未定义 token 均为 0）。
- **落地路径**：`apps/desktop/src/styles/tokens.css`；对比度校验脚本 `scripts/check-tokens.mjs`
  待落地阶段实现并接入 CI（tokens.md §9-E2/E3）。

## 4. 核心页面信息架构（详见 ia-and-interaction.md）

**单窗口 + 三主干视图 + 右侧检查器**（否决多窗口与单页长滚动）：

- 左栏（248px / 折叠 64px）：应用头 + 新建对话 + 一级导航（对话/记忆/任务）+ 会话列表 + 设置。
- 中间聊天主列：内容区 max-width 760px 居中——**唯一的注意力中心**。
- 右侧检查器 320px（`--ap-size-detail`）：记忆详情/任务详情/工具详情共用；compact 断点以下转覆盖式浮层。
- 断点 5 档（xs/sm/md/lg/xl），最小可用宽 1024px；窗口 1280×840 启动，min 1024×640。

**聊天主界面**：消息流四层（L0 日期分隔 → L1 回合 → L2 块序列 text/tool_call/error/plan-note
严格按后端事件序 → L3 行内元信息悬停显形）。助手侧**不用气泡**（文档流 + 卡片，保住工具卡片层级），
用户侧保留气泡。流式：首 token ≤5s、16ms 帧节流、48px 滚动锚定、块落地微动效。
输入区：IME 组合期间 Enter 不发送（硬要求）、乐观发送+失败回填、流式中第二条排队可观测、
附件/斜杠均为诚实的"二期"占位（**不制造未实现能力的假象**）。九类错误逐一定义（行内错误条，
不用 toast），重连/只读/重启恢复全有形态。

**工具调用呈现**：卡片四层（头部/参数摘要/结果摘要/展开详情），与 `tool_calls` 行一一对应；
危险三级视觉区分（safe/caution/danger）；**边界触发的就地非模态确认**（域内写直接执行，
越界写与命令执行就地确认，`允许一次` 一次性语义）；写文件落盘校验三项（行数/字节/mtime/路径存在）；
失败自动展开；未列表工具保守降级形态，禁止无参数摘要的卡片。

**记忆视图**：偏好/事实两类 + 子串搜索（向量检索二期）；来源可追溯（点击回原对话定位高亮）；
查看/删除（行内确认 + 5s 撤销），**编辑与手动新增为二期**；声称"已记住"但无 `memory_write`
卡片时给行内警告（CP-02 的 UI 呈现）。

**任务视图（轻量，不做 Kanban）**：纵向列表 + 检查器详情，只回答三问：在做什么/做完没有/
凭什么说做完。终态徽标 + 锁定图标 + 终态冲突显式提示（AT-503）；CAS 领取冲突可见（AT-009）；
限额/拒绝记录原文可见（AT-505/506）；事件时间线 metadata-only。

**陪伴感微交互**：收敛为少数 ≤24px 的 presence 元素 + 分级交互时间轴（250ms 打字指示 / 2.5s「正在思考…」/
8s 提示可 Esc / 30s 超时）；presence idle 完全静态（不假装活着），"送达感"由 `--ap-ease-settle`
一次性确认曲线承担（限工具成功/记忆写入，每回合最多一次）；awaiting 态静止实心 + 外环（硬规则）；
无桌面通知/任务栏闪烁/红点。

## 5. 治理语义的视觉编码（本设计最关键的正确性决策）

| 治理语义（t1 P0 / t7） | UI 编码 |
|---|---|
| 终态不可降级 | 终态徽标 + 12px 锁定图标 + 无状态变更入口；收到冲突更新时**保持终态显示** + 显式错误条 |
| 进度文本 ≠ 交付 | 「◷ 仅计划，尚未执行」（warning）vs「✓ 已核验交付 · 依据 <工具>×N」（success）双形态；**前端不做时态推断**，只消费后端 `turn.delivery` 字段；字段缺失渲染为「未提供交付状态」，禁止把未知渲染为成功 |
| 显式报错不静默降级 | denied 卡片展示拒绝/拦截原因原文；沙箱拦截绝不显示为"成功但无输出"；确认不设自动超时 |
| CAS 领取 | 冲突提示条 + 不出现第二个 running 指示 |
| 三层限额 | 限额拒绝文案含上限数值，行内可见 |
