> 输入：已定方向（私人助理 / 最小本地 / TS 同仓）+ t1 对标结论
> （`docs/decisions/t1-reference-benchmark.md`）。本稿只做规划，供用户最终拍板；
> 拍板后 t3 建仓、t4/t5/t6/t7 依此展开。

## 1. 产品定位

**一句话：单人自托管的私人 AI 助理——本地可跑、有记忆、能办事，网关与图形入口随身。**

- 对标形态：openclaw/hermes 的个人助理形态（单用户常驻），体验差异化看 openhanako
  的桌面/办公侧（书桌、人格、多平台触达）——但验收强度反其道而行之：硬 verdict 门禁。
- 目标用户：个人重度用户（开发者与知识工作者），一台机器自托管。
- 核心场景（按优先级）：日常陪伴问答 → 办事执行（文件/命令/网页/搜索）→
  记忆沉淀（跨会话记住人与事）→ 定时任务（cron 提醒/巡检，二期）。
- 非目标（明确不做）：企业多租户、coding-agent-first、manager-of-managers
  默认层级编排（openclaw VISION 已证伪此路）、重型 Kanban/swarm（均放二期后）。

## 2. MVP 边界：最小本地可用

MVP 定义：**单人、单机、单 Agent，能聊、能干活、能记住，下线重开不丢人。**

### In scope（MVP 必须有）

1. 聊天主循环：单 Agent 会话（多轮对话 + 流式输出）。**M1 入口 = Electron 桌面端优先；
   Web 仅为调试/次入口**（与 Out of scope 对齐：桌面端在 MVP 内）。
2. 工具调用：读/写文件、执行命令、网页浏览/搜索——最小工具集，窄腰纪律
   （新能力先 skill/插件/MCP，最后才加核心 tool）。
3. 简单记忆：跨会话持久记忆（偏好、事实），SQLite 本地落盘。
4. 本地状态内核：SQLite 单文件（WAL），任务/会话/记忆同库；终态不可降级。
5. P0 治理（抄 t1 清单 1–5）：终态语义、CAS 领取、进度文本≠交付、
   子权限不超父（MVP 单 Agent 先行，此条为二期预置）、三层限额初版。
6. 可发布：本地一键可跑 + 真实构建产物（配合 t7 本地真实发布验收，防假绿）。

### Out of scope（明确二期）

- 网关（多渠道消息接入：Telegram/飞书/QQ/微信等）
- 多 Agent（委派、群聊协作、swarm/Kanban）
- 定时任务 / cron / 心跳巡检
- 移动端 PWA（M3 才做；桌面端 Electron 在 MVP 内，不在此列）
- 技能沉淀闭环（curator）、LLM-as-judge、journal 断点恢复、草稿卡审批
- 插件市场/生态

### 技术栈（已定）

- TS 全栈同仓：pnpm monorepo（对标 openclaw `packages/* + extensions/*` 形态），
  单一包管理；SQLite 为唯一运行时状态存储（无 Redis/MQ）。
- 建仓节奏：本稿拍板 → t3 建仓与 CI 规范 → t4/t5 并行规划。

## 3. 路线图

- M1（MVP）：本地桌面聊天 + 工具 + 记忆 + SQLite + P0 治理 + 真实发布验收。
- M2：网关（先 1–2 个渠道）+ 定时任务 + 多 Agent（depth 1 先行）。
- M3：移动端 PWA / 技能闭环 / 插件生态（按 M2 反馈再排；桌面端已在 M1，不在此列）。

## 4. MVP 验收口径（交 t7 细化）

1. 全新机器按文档一次跑通（真实构建产物，非 dev-only）。
2. Agent 点击链路端到端可走通（聊天→工具→记忆→重启不丢）。
3. P0 治理逐条可演示（终态/进度文本/限额至少三项）。
4. 文档节制：AGENTS.md + design.md + 本系列决策文档齐备。

## 5. 用户拍板结果（2026-09-11）

1. **定位**：接受"单人自托管的私人 AI 助理"。
2. **MVP 入口**：桌面优先（原草案 Web 优先已修正）。
3. **记忆深度**：偏好+事实简单记忆，向量检索放二期。
4. **工具边界**：允许 shell 命令，沙箱初版约束（t4 给方案）。
5. **M2 顺序**：网关先（1–2 个渠道），再多 Agent。
